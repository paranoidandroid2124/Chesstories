# 독립 앱 기준 정리와 복구 — 2026-10-13

이번 정리는 `chesstory-web/`와 `chesstory-runtime/`를 제품 개발·실행 기준으로 삼습니다.
해설의 새 목적 발견이나 일반화 개선을 주장하는 작업은 아닙니다.
이전 연구 문장·판정·기준과 미커밋 변경은 보존했습니다.

## 정리 범위

- 옛 `lila-docker/`의 서버·배포·번역·화면과 임시 호환 경로를 제품 폴더에서 제외했습니다.
- 폴더 삭제는 자동 승인 검토에서 차단되어, 원본 전체를 아래 작업 보관 폴더로 이동했습니다.
  디스크에서 원본을 영구 삭제하거나 저장 공간을 회수한 것으로 세지 않습니다.
- 일반 분석·해설이 이미 공통으로 사용하던 제한된 UCI 경로를 남기고 옛 일반 분석 분기를 제거했습니다.
- 독립 앱에서 쓰지 않는 엔진 목록·아이콘 글꼴 변환·스터디 저장 버튼·빈 연결 함수를 제거했습니다.
- 핵심 해설 소속·깊이·취소 검사를 유지했고, 기존 검사 24개 파일과 지원 모듈 1개를 독립 앱으로 옮겼습니다.

## 기존 실패 기준

[10월 10일 중복 조사](../functional-judgment-20261009/duplication-audit-20261010.json)의
전체 검사 실패(Runtime 75, UI 124)는 당시 기준에서 재현된 미해결 이력입니다.
이번에 그 실패가 해결됐거나 해당 검사가 모두 불필요해졌다고 판정하지 않았습니다.

[검사 이동 목록](test-migration.json)에 38개 기존 해설 관련 파일의 행선지를 기록했습니다.
25개 파일은 `chesstory-web/tests/regression/`로 옮겼고, 참조 목적 검사는 직전 분리에서 이미 이동했습니다.
나머지 12개는 옛 Lila 컨트롤러·스터디·DOM 실행기에 의존하거나, 현재 정리본에 없는 과거 자료를 참조합니다.
그 원본과 실패 기준은 아래 보관본/Git 이력에 남습니다. 실패를 숨기기 위해 조건을 완화하지 않았습니다.

옮긴 검사의 기본 수정은 가져오기·자료 경로입니다. 엔진 프로토콜 검사 한 곳은 폐기한 Lila의
Chess960 표기 복귀 대신, 일반 분석과 해설이 같은 표준 체스 표기와 준비 경계를 쓰는지 확인하도록
수정했습니다. 취소 뒤 통계·늦은 PV의 소속 검사와 같은 깊이의 PV 교체 검사는 유지했습니다.
역사적 D20 기록은 기존 저장 자료이며, 이번 실제 엔진 탐색은 D18을 넘기지 않았습니다.

이번에는 이 검사 전체를 실행하지 않았습니다. 25개 파일의 독립적인 빌드 연결만 확인하고,
실제 화면의 기보 입력·체스판·분석·해설·국면 링크·저장 흐름을 확인했습니다.

## 보존 위치와 복구

기준 Git 커밋은 `c73eb64117ae2fde3bde9267c935e092b6672d9b`입니다. 커밋·스테이징은 하지 않았습니다.

1. 현재 작업트리의 `target/research-runs/standalone-cleanup-20261013/retired-lila-docker/`에
   옛 디렉터리 원본을 그대로 보관합니다. 이전 환경을 살필 때는 이 폴더를 별도 복구 폴더로 복사하면 됩니다.
2. 같은 작업 보관 폴더의 `lila-working-tree.zip`에는 미커밋 파일과 무시된 의존성까지 포함한 전체 복사본이 있습니다.
   압축 전·후의 파일별 SHA-256과 원본 바이트를 대조했으며, 목록은 `legacy-manifest.json`입니다.
3. 이 폴더의 [pre-cleanup-changes.zip](pre-cleanup-changes.zip)은 Git에 없는 변경도 남기기 위한 작은 보관본입니다.
   옛 Lila의 미커밋 파일과 독립 앱의 정리 전 소스 60개를 원본 바이트로 보관합니다.
   `working-state.json`에 경로·상태·해시, `BASE_COMMIT.txt`에 기준 커밋이 있습니다.
4. 로컬 `target/`가 없어진 경우에는 위 Git 커밋의 `lila-docker/`를 **빈 별도 복구 폴더**에 내보낸 뒤,
   이 작은 보관본의 `lila-docker/`를 덮어 씌우면 정리 직전의 소스를 복원할 수 있습니다.
   `chesstory-web/`도 함께 보관되어 있어 정리 전 공통 소스와 대조할 수 있습니다.
   무시된 설치 의존성은 전체 보관본을 쓰거나 해당 잠금 파일로 다시 설치해야 합니다.

활성 작업트리의 최신 소스 위에 복구본을 덮어쓰지 마세요. 이 보관본은 복구와 대조용이며 현재 빌드 입력이 아닙니다.
